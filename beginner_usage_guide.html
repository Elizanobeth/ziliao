1. 这个工具到底做什么

这个工具用来解决“晶圆 Die 怎么分配到多个母批里，才能尽量接近客户要的 Unit 数，同时尽量少浪费 Die”的问题。

它会读取一个 Excel 文件，从里面找到某个产品、某个供应商、某些 Bin Grade 的 Die 数量，然后按照规则表里的层数配比，比如 2:6，自动规划每个母批用哪些 Lot、哪些 wafer、哪些 Bin Grade，以及这些 Die 分到工艺 A 还是工艺 B。

你可以把它理解成一个自动配料工具。 客户要做一定数量的 Unit，每个 Unit 都需要 A 工艺 Die 和 B 工艺 Die。Excel 里有很多 Lot、wafer、Bin Grade 的库存，这个工具帮你挑组合。

2. 先用一句话理解业务

一个 Unit 需要两类 Die，比例由规则表决定；每个 Lot 一旦被选中，就要把用户选择的 Bin Grade 范围内的 Die 配完；每个母批有 Unit 上限、Lot 数上限和损耗上限；最后总 Unit 数要尽量接近目标。

层数配比 例如 2:6，表示 1 个 Unit 需要 2 颗 A 工艺 Die 和 6 颗 B 工艺 Die。
母批 一次分配结果里会有多个母批，每个母批有自己的 Unit 数、Lot 列表和损耗。
目标 不是必须大于目标，而是尽量接近目标。低一点或高一点都可以，谁更接近谁优先。

3. 你需要准备什么文件

你需要准备一个 Excel 文件，后缀一般是 .xlsx。这个文件里面必须有两个 Sheet：

Sheet 名 作用 小白解释
原始数据 存放每个 PACKAGE、供应商、Lot、wafer、Bin Grade 的 Die 数量。 这张表就是“库存表”。工具从这里找可用 Die。
配die 规则表 存放每个 PACKAGE、供应商对应的层数配比。 这张表就是“配方表”。工具从这里知道 1 个 Unit 要几颗 A、几颗 B。
Sheet 名必须完全一致。 例如 原始資料、原始 数据、配Die规则表 都不行。大小写、空格、中文都要按要求来。

4. Excel 两个 Sheet 怎么填

4.1 原始数据 必须有这些列

列名 必须吗 含义 例子 注意事项
PACKAGE 必须 产品类型或封装名。 PKG-D400、PKG D400 RevC 可以和规则表不完全一样，工具会做模糊匹配，但不要太离谱。
供应商 必须 供应商名称。 中芯国际、台积电 这个字段按精确匹配处理，建议两个 Sheet 写法保持一致。
Fab LotID 必须 Lot 编号。 FAB-SMIC-2618-0001 同一个 Lot 一旦参与分配，就要配完用户选择 Grade 范围内的 Die。
Bin Grade 必须 Die 等级。 1、2、9、X 只允许 1 到 9 和 X。
Bin Quanity 必须 该 Grade 的 Die 数量。 2130 注意列名就是 Quanity，不是 Quantity。数量必须是非负整数。
T7 Code 必须 wafer 唯一识别码。 T7-D400-000001-01 工具用 Fab LotID + T7 Code + Bin Grade 作为最小供应单元。

4.2 配die 规则表 必须有这些列

列名 必须吗 含义 例子 注意事项
PACKAGE 必须 规则表里的产品类型。 PKG-D400 工具会用用户输入的 PACKAGE 在这里先找对应规则。
供应商 必须 供应商名称。 力积电 必须能和原始数据、用户输入对上。
层数配比 必须 一个 Unit 需要的 A/B 工艺 Die 比例。 2:6、4:4 只能是两个正整数，中间用冒号。不能写 2/6、2：0 或 2.5:5.5。
最常见的 Excel 问题： 列名写错、Sheet 名写错、数量列有空值、数量列有小数、供应商名称多了空格、Bin Grade 写成了不支持的值。

5. 运行前必须确定的参数

运行工具时，你需要告诉它下面这些信息。不要随便猜，尤其是损耗、Unit 上限、Lot 上限和复用规则。

参数 命令里怎么写 意思 例子 怎么决定
Excel 文件路径 --workbook 输入工作簿的位置。 input.xlsx 用你的真实 Excel 文件路径。
产品 --package 你要配哪个 PACKAGE。 "PKG D400 RevC" 可以写原始数据里的名称，也可以写规则表里的名称；工具会匹配。
供应商 --supplier 你要配哪个供应商的数据。 "力积电" 必须和表格里的供应商一致。
目标 Unit 数 --target-units 客户希望得到多少 Unit。 40000 或 40k 40k 表示 40000。
Bin Grade --grades 只使用哪些等级的 Die。 1,2,3 只会配完你选择范围内的 Die，未选择的 Grade 不参与。
单母批最大损耗 --loss-cap 每个母批最多允许浪费多少颗 Die。 30 注意是每个母批，不是所有母批合计。
单母批最大 Unit --unit-cap 一个母批最多能出多少 Unit。 4500 或 4.5k 如果设太小，可能找不到方案。
单母批最大 Lot 数 --lot-cap 一个母批最多允许多少个不同 Lot。 5 如果和 Unit 上限冲突，工具会先保证 Unit 相关硬约束，再尝试放宽 Lot 数。
Lot 复用规则 --reuse-rule Lot 是否允许跨母批。 allow_reuse 或 no_reuse 可以写中文：允许复用 或 不允许复用。
输出目录 --out-dir 结果文件放在哪里。 outputs/run-001 每次运行建议换一个新目录，避免覆盖旧结果。

6. backend 怎么选

backend 是“求解方式”。当前只有三个正式选项：auto、cpsat、large_batch。

backend 适合什么情况 输出状态可能是什么 小白建议
auto 默认选择。小数据优先精确搜索；数据大或搜索空间太大时切到大表模式。 OPTIMAL 或 FEASIBLE 第一次使用就选它。
cpsat 强制精确搜索。适合小数据、需要证明最优的情况。 OPTIMAL、SEARCH_LIMIT、报搜索空间过大 只有数据规模可控、你确实要精确最优时再用。
large_batch 大表模式。适合行数很多、Lot 很多、最小供应单元很多的业务数据。 FEASIBLE 或 INFEASIBLE 数据很多时用它，速度更稳，但不声明数学全局最优。
只使用这三个正式选项。 命令里的 --backend 只能填写 auto、cpsat 或 large_batch。

几个状态是什么意思

状态 意思 能不能用
OPTIMAL 在当前模型和当前搜索空间内，已经证明是最优。 可以作为精确最优结果使用。
FEASIBLE 找到了满足硬约束的可行方案，但不声明全局最优。 业务上通常可以看，但要知道它不是数学证明最优。
INFEASIBLE 没有找到可行方案。 不能直接用，需要调整条件或检查数据。
SEARCH_LIMIT 搜索达到上限，没法证明最优。 要么放宽搜索上限，要么使用 large_batch。

7. 这个 Skill 的求解原理

这一节讲“工具为什么能算出结果”。尽量不用数学语言，先讲大流程，再讲大表模式 large_batch 怎么找候选母批，最后讲精确模式 cpsat 怎么完整搜索并证明最优。

7.1 总体流程：先整理数据，再求解，再校验

这个 Skill 不是一上来就直接配 Die。它会按固定顺序做 5 件事：

步骤 做什么 小白理解
1. 校验 Excel 检查 Sheet、列名、数量、Bin Grade 是否合法。 先确认“库存表”和“配方表”能不能用。
2. 匹配规则 按 PACKAGE + 供应商找到层数配比。 先知道 1 个 Unit 到底要几颗 A、几颗 B。
3. 构建供应单元 只保留用户选择的 Grade，并按 Fab LotID + T7 Code + Bin Grade 聚合。 把原始明细整理成一块块“可分配材料”。
4. 求解分配 根据 backend 选择精确搜索或大表搜索。 开始挑哪些 Lot / wafer / Grade 放进哪些母批。
5. 校验并导出 检查重复分配、Lot 是否配完、损耗和 Unit 上限是否满足。 算完后再复查一遍，最后生成 Excel 报告。
关键点： 求解器给出的结果不会直接“裸奔”给用户。它会再经过 checks 校验，确认所选 Grade、Lot 配完、重复分配、单母批损耗、单母批 Unit 上限等规则是否满足。

7.2 什么叫“候选母批”

候选母批可以理解为“一个可能可用的母批组合”。它还不是最终答案，只是一个候选。

一个候选母批里面会记录这些信息：

信息 含义
包含哪些 Lot 这个母批用了哪些 Fab LotID。
包含哪些最小供应单元 具体用了哪些 Fab LotID + T7 Code + Bin Grade。
A 侧 / B 侧怎么分 每个供应单元分到 A 工艺侧还是 B 工艺侧。
能做多少 Unit 由 A 侧数量、B 侧数量、层数配比和 unit_cap 共同决定。
损耗是多少 实际投入 Die 数减去理论消耗 Die 数。
Lot 是否超限 候选母批不同 Lot 数是否超过 lot_cap。

7.3 一个候选母批怎样才算合格

工具生成候选母批后，会立刻检查它是否合格。不合格的候选不会进入后面的选择阶段。

检查项 要求 不满足会怎样
A/B 工艺数量 A 侧 Die 数必须足够支撑 rA * Unit，B 侧 Die 数必须足够支撑 rB * Unit。 这个候选不能用。
Unit 上限 候选母批的 Unit 数不能超过 unit_cap。 Unit 会被限制在上限以内。
损耗上限 候选母批损耗必须小于等于 loss_cap。 超过则丢弃。
Lot 数上限 严格阶段不同 Lot 数必须小于等于 lot_cap。 严格阶段丢弃；放宽阶段会记录 Lot 超限量。
至少能做 1 个 Unit 候选母批必须能生产正数 Unit。 不能做 Unit 的候选会丢弃。

7.4 A 侧和 B 侧怎么分

一个候选母批拿到一组供应单元后，还要决定哪些放 A 侧、哪些放 B 侧。

工具会按层数配比尽量把 A/B 两侧分得合理，并在可行前提下优先选择：

  1. Unit 数更高的分法。
  2. 损耗更低的分法。
  3. A/B 比例更接近层数配比的分法。

如果候选里的供应单元数量不多，工具会枚举 A/B 分法；如果供应单元很多，工具会用稳定的确定性分法，把数量尽量往 rA : rB 靠近。这样大表不会因为 A/B 分边而变得特别慢。

7.5 large_batch 为什么要先生成候选母批

大表里 Lot 和 wafer 很多，如果把所有供应单元和所有母批的所有可能分配都列出来，组合数量会非常夸张，计算可能跑不完。

large_batch 的思路是：

  1. 先生成一批质量较高、看起来有希望的候选母批。
  2. 再从这些候选母批里挑互相不冲突的一组。
  3. 最后比较哪组结果更接近目标 Unit、损耗更低、Lot 超限更少。
所以 large_batch 很适合大数据稳定出方案。 但它不会枚举所有可能组合，因此结果状态是 FEASIBLE，不能说成数学全局最优。

7.6 large_batch 怎么生成候选母批

大表模式下，工具主要按 Lot 来生成候选母批。它会先计算每个 Lot 的总 Die 数，然后用几种固定排序去看 Lot 的组合。

排序方式 为什么这么排
Lot 总 Die 数从大到小 优先尝试大 Lot，可能更快凑出较大的母批。
Lot 总 Die 数从小到大 小 Lot 有时更容易减少超配和损耗。
Lot 总量对 rA + rB 的余数从小到大 余数小的 Lot 组合更可能减少除不尽造成的损耗。
Lot 名称字典序 保证结果稳定，同样输入下顺序固定。

在每一种排序里，工具会先用“连续窗口”的方式生成基础候选：

  1. 从排序后的第 1 个 Lot 开始，尝试 1 个 Lot、2 个 Lot、3 个 Lot……
  2. 再从第 2 个 Lot 开始重复同样操作。
  3. 窗口最多包含多少个 Lot，由 max_combo_lots 控制。
  4. 严格 Lot 数阶段，窗口大小不能超过 lot_cap。
  5. 放宽 Lot 数阶段，窗口可以适当超过 lot_cap，但会记录 Lot 超限。
  6. 重复出现过的 Lot 组合会跳过，避免重复计算。
  7. 候选数量达到 candidate_limit 后停止生成。
连续窗口是什么意思？ 假设排序后是 Lot A、Lot B、Lot C、Lot D，窗口组合会尝试 A，A+B，A+B+C，然后 B，B+C，B+C+D。这样比所有 Lot 任意组合快很多，也更稳定。

为了避免候选太少，现在 large_batch 还会额外生成两类非连续候选：

扩展方式 怎么选 为什么有用
非连续近邻组合 在排序后的一个小范围窗口里，允许跳过中间 Lot，尝试非连续 Lot 组合。 避免只因为 Lot 排在中间不同，就错过更低损耗或更接近目标的组合。
余数优化组合 优先挑选总量对 rA + rB 余数较友好的 Lot 组合。 余数更友好的组合，通常更容易减少除不尽带来的 Die 损耗。
非连续扩展不是无限全组合。 它仍然受 candidate_limit 控制，并且会限制非连续组合的规模。这样可以增加候选丰富度，同时避免大表计算失控。

7.7 allow_reuse 时有什么特殊处理

如果允许复用，同一个 Lot 可以跨多个母批，但仍然必须保证：这个 Lot 在用户选择 Grade 范围内的供应单元要被完整覆盖，且同一个最小供应单元不能重复。

因此 large_batch 在 allow_reuse 时会多做一步：

  1. 先尝试整 Lot 候选。
  2. 如果某个 Lot 不能作为单个整 Lot 候选进入方案，就尝试把这个 Lot 内的供应单元切成几个母批候选。
  3. 切分时会按几种固定顺序尝试：数量从大到小、数量从小到大、Grade 顺序结合数量排序。
  4. 每个切出来的小候选也必须满足 Unit、损耗、A/B 分配等规则。
  5. 这些小候选合起来必须覆盖该 Lot 在所选 Grade 范围内的全部供应单元，才会作为一个计划进入选择阶段。

这样做的目的，是让允许复用场景下同一个 Lot 可以被拆到多个母批，但仍然不破坏“Lot 所选 Grade 必须配完”和“同一最小供应单元不能重复”的规则。

7.8 怎么从候选母批里挑最终方案

候选母批生成后，工具会把候选包装成“计划”，然后从计划里挑一组不冲突的方案。

选择时先按下面顺序排序：

  1. 单位损耗低的优先，也就是 loss / units 小的优先。
  2. Lot 超限少的优先。
  3. Unit 数高的优先。
  4. 启用母批少的优先。
  5. 最后按计划 ID 保持稳定顺序。

然后逐个尝试加入计划：

检查 规则
最小供应单元冲突 如果一个计划用了已经被选过的供应单元，就跳过。
不允许复用时的 Lot 冲突 no_reuse 下，如果计划用了已经被选过的 Lot，就跳过。
目标接近度 如果加入这个计划会让整体目标更差，通常跳过。
达到目标附近 如果已经达到或超过目标，先停止继续加入，再做后续修剪。

7.9 为什么选完后还要“修剪”

有时连续加入候选后，总 Unit 可能超过目标，或者某个已选计划让整体离目标更远。工具会再尝试删除已选计划：

  1. 把已选计划逐个拿掉试一下。
  2. 如果拿掉后整体更接近目标，或者损耗、Lot 超限、母批数更好，就真的删除。
  3. 重复这个过程，直到删不动为止。

这一步可以减少明显不必要的超配，让结果更贴近目标 Unit。

7.10 严格 Lot 数阶段和放宽 Lot 数阶段

large_batch 会按两个阶段尝试：

阶段 含义 结果怎么看
严格 Lot 数阶段 每个母批不同 Lot 数必须小于等于 lot_cap。 如果这个阶段找到好方案，通常优先。
放宽 Lot 数阶段 允许母批 Lot 数超过 lot_cap，但会记录 lot_overflow。 只有当它能带来更接近目标的结果时才可能被选中。

最后工具会比较两个阶段的结果，按固定目标优先级选择更好的那个：先看 Unit 差距，再看总损耗，再看 Lot 超限，再看母批数。

7.11 哪些参数会影响 large_batch 的结果

参数 影响
candidate-limit 候选母批最多生成多少个。太小可能错过好组合，太大计算更慢。
max-combo-lots 单个候选最多尝试多少个 Lot。连续窗口会按这个上限走；非连续扩展会额外做固定保护，避免大表失控。
max-side-items A/B 侧精确枚举分配的最大供应单元数。超过后使用确定性分法。
loss-cap 越严格，候选越少；越放宽，候选可能更多，但损耗也可能增加。
unit-cap 限制单母批最大 Unit，影响候选能做多大。
lot-cap 限制单母批 Lot 数，影响严格阶段候选数量。
grades 决定哪些 Die 进入计算，直接影响可用总量和 Lot 配完范围。
reuse-rule 决定计划之间能否共享 Lot，影响组合自由度。

7.12 cpsat 是什么

cpsat 是精确搜索后端。当前 Skill 里的 cpsat 不依赖 OR-Tools，而是使用纯 Python 完整枚举 + 分支定界来求解。

它和 large_batch 最大的区别是：

对比项 cpsat large_batch
搜索方式 在上限允许范围内完整枚举候选母批，并用分支定界选择最优组合。 生成一批高质量候选母批，再用确定性规则挑可行方案。
结果状态 完整搜索完成且未触发上限时，可以输出 OPTIMAL。 输出 FEASIBLE，不声明全局最优。
适合规模 适合小数据、组合数量可控的场景。 适合大表、Lot 多、wafer 多、最小供应单元多的场景。
遇到组合爆炸 会报搜索空间超过上限，或者返回 SEARCH_LIMIT。 会继续尝试生成有限候选，给出稳定可行解。
为什么还叫 cpsat？ 名字保留了“精确约束求解”的含义，但当前实现是纯 Python 精确搜索，不需要安装 OR-Tools。

7.13 cpsat 怎么生成候选母批：不允许复用

如果 reuse_rule=no_reuse，同一个 Lot 只能出现在一个母批里，所以精确模式会按 Lot 组合来枚举候选母批。

它会这样做：

  1. 先把可用供应单元按 Lot 分组。
  2. 严格 Lot 数阶段，只枚举 1 个 Lot、2 个 Lot……直到 lot_cap 个 Lot 的组合。
  3. 放宽 Lot 数阶段，会枚举更多 Lot 组合，并记录超出 lot_cap 的数量。
  4. 如果需要枚举的 Lot 组合数超过 exact-max-combinations，就停止并报“搜索空间过大”。
  5. 每个 Lot 组合会先检查总 Die 数是否可能放进一个母批。
  6. 通过初筛后，再做 A/B 侧精确分配，判断它能不能成为一个合格候选母批。

这就是为什么小数据时 cpsat 可以证明最优：它不是只看几个看起来不错的组合，而是在上限内把所有相关 Lot 组合都试过。

7.14 cpsat 怎么生成候选母批：允许复用

如果 reuse_rule=allow_reuse，同一个 Lot 可以跨母批，所以不能只按 Lot 组合枚举。此时精确模式会按“最小供应单元”组合来枚举。

最小供应单元仍然是：

Fab LotID + T7 Code + Bin Grade

枚举逻辑是：

  1. 把所有最小供应单元按数量、Lot、wafer、Grade 排成固定顺序。
  2. 递归尝试不同供应单元组合。
  3. 如果某个组合总 Die 数已经超过单母批最大可容纳量，就停止往这个方向继续加。
  4. 严格 Lot 数阶段，如果组合里的不同 Lot 数超过 lot_cap，就跳过。
  5. 枚举前会先做快速计数预检；如果组合数量已经超过 exact-max-combinations，直接报搜索空间过大。
  6. 通过组合数量检查后，才真正生成候选，并做 A/B 侧精确分配。
allow_reuse + cpsat 更容易组合爆炸。 因为它不是按 Lot 组合，而是按更细的最小供应单元组合来枚举。大表时通常建议使用 auto 或 large_batch。

7.15 cpsat 的 A/B 侧为什么更精确

在 cpsat 中，一个候选母批拿到一组供应单元后，会用类似 subset-sum 的方式精确寻找 A 侧 Die 数。

通俗讲，它会尝试：

  1. 这些供应单元里，哪些放 A 侧。
  2. 剩下的自然放 B 侧。
  3. 计算 A 侧和 B 侧分别能支撑多少 Unit。
  4. 计算损耗是否小于等于 loss_cap。
  5. 在所有可行 A/B 分法里，优先选 Unit 数最高、损耗最低、A/B 比例最贴近层数配比的分法。

如果候选母批的总 Die 数超过 exact-side-sum-limit，工具会停止并提示 A/B 精确分配空间过大。这样做是为了避免在特别大的候选上无限计算。

7.16 cpsat 怎么从候选母批里选最终方案

生成候选母批后，cpsat 会用分支定界来选择最终方案。你可以把它理解成“每个候选都认真考虑选或不选，但会剪掉明显不可能更好的路”。

它会按下面方式搜索：

步骤 说明
候选排序 先按 Unit 数高、损耗低、Lot 超限少等规则排序，让好候选优先被尝试。
尝试选择 对每个候选，递归尝试“选它”和“不选它”两条路。
冲突检查 同一个最小供应单元不能重复选；no_reuse 下同一个 Lot 也不能重复选。
Lot 配完检查 allow_reuse 下，如果某个 Lot 被碰到，最终必须覆盖该 Lot 在所选 Grade 范围内的全部供应单元。
目标比较 比较 abs(total_units - target_units)、总损耗、Lot 超限、母批数和是否超目标。
剪枝 如果剩下候选就算全加上也不可能超过当前最好结果，就提前停止这条路。

7.17 cpsat 的最优目标顺序

cpsat 不是简单追求 Unit 越多越好，而是按固定顺序比较方案：

  1. 总 Unit 离目标 Unit 越近越好。
  2. 如果 Unit 差距一样，总损耗越小越好。
  3. 如果进入放宽 Lot 数阶段，Lot 超限越少越好。
  4. 如果还一样，启用母批数越少越好。
  5. 如果仍然一样，优先选择不超过目标的方案，减少超配。

所以目标 10000 时，9900 和 10100 的 Unit 差距一样；如果其他指标也一样，工具会优先选 9900，避免超配。

7.18 cpsat 什么时候能说 OPTIMAL

只有同时满足下面条件，cpsat 才能输出 OPTIMAL：

  1. 候选母批枚举没有超过 exact-max-combinations。
  2. A/B 侧精确分配没有超过 exact-side-sum-limit。
  3. 分支定界选择阶段没有超过 node-limit。
  4. 搜索完整结束，并找到了当前目标顺序下最好的方案。

如果触发上限，工具不会假装最优。它会：

情况 工具行为 用户怎么处理
候选组合超过上限 报搜索空间过大。 改用 auto 或 large_batch，或提高 exact-max-combinations。
A/B 侧分配超过上限 报 subset-sum 空间过大。 改用 large_batch，或提高 exact-side-sum-limit。
分支定界超过节点上限 返回 SEARCH_LIMIT，不声明最优。 提高 node-limit，或改用 large_batch。
cpsat 一句话总结： 它在可承受规模内完整枚举候选母批，再用分支定界选择最接近目标的全局最优方案。它更精确，但对数据规模更敏感。
一句话总结： 小数据想证明最优，用 cpsat；大数据想稳定出可行方案，用 large_batch；不确定时用 auto，让工具自己选择。

11. 关键业务规则解释

11.1 只配用户选择的 Bin Grade

如果你输入 --grades 1,2,3，工具只看 1、2、3 这三个等级。4、5、6、7、8、9、X 都不参与本次计算。

Lot 必须配完，也只针对你选择的 Grade 范围。也就是说，Lot 下未选择的 Grade 不会被强制配完。

11.2 最小供应单元是什么

工具会把 Fab LotID + T7 Code + Bin Grade 聚合成一个最小供应单元。默认情况下，这个单元是整体分配的，不会拆成半个给这个母批、半个给那个母批。

11.3 不允许复用

如果写 --reuse-rule no_reuse，一个被使用的 Lot 只能出现在一个母批中。因为 Lot 一旦被选中，该 Lot 在所选 Grade 范围内的所有最小供应单元都要配完，所以同一片 wafer 也只会出现在这个母批里。

11.4 允许复用

如果写 --reuse-rule allow_reuse，同一个 Lot 可以出现在多个母批中。同一片 wafer 也可能因为不同 Bin Grade 被分到不同母批。但是同一个最小供应单元不能重复分配。

11.5 损耗约束是单母批约束

--loss-cap 30 表示每个母批最多浪费 30 颗 Die，不是所有母批加起来最多 30。比如两个母批分别损耗 20 和 27，总损耗是 47，但每个母批都没有超过 30，所以仍然符合这个约束。

11.6 目标 Unit 是“最接近”，不是“必须大于”

现在的目标是最小化 abs(总 Unit - 目标 Unit)。例如目标是 10000，结果 9900 和 10100 的差距都是 100。如果其他条件相同，工具会优先选择不超过目标的方案，减少超配。

12. 注意事项和避坑

  1. 不要把 Bin Quanity 改成 Bin Quantity。 当前工具按业务表字段读取，列名必须是 Bin Quanity。
  2. 供应商名称要统一。 台积电 和 TSMC 不会被当成同一个供应商，除非表里本来就是同一个写法。
  3. PACKAGE 可以模糊匹配，但不要依赖它猜复杂歧义。 如果同一个供应商下有多个非常相似的 PACKAGE，最好输入更明确的名称。
  4. 每次运行都换输出目录。 否则新结果可能覆盖旧结果。
  5. 大表不要强行用 cpsat。 精确搜索在大表上可能组合爆炸，这是数学问题，不是代码坏了。
  6. large_batch 是可行解，不是全局最优证明。 它适合业务大数据稳定出结果，但不要把 FEASIBLE 写成 OPTIMAL。
  7. 如果总 Die 数不够，工具仍会找最接近目标的方案。 这时不要说“满足目标”，应说“当前约束下最接近目标”。
  8. 如果 checks 里有 false，不要直接使用结果。 先排查校验失败原因。
  9. 如果损耗看起来超过上限，先看是不是总损耗。 上限是单母批上限，总损耗可以大于单母批上限。
  10. 不要手改中间 JSON 后继续跑，除非你很清楚自己在做什么。 小白只建议用总入口脚本端到端跑。

13. 常见报错怎么处理

看到的现象 可能原因 怎么处理
提示缺少 Sheet Excel 里没有 原始数据 或 配die 规则表。 检查 Sheet 名，必须一字不差。
提示缺少字段 列名写错或漏列。 按本文第 4 节检查所有必填列。
Bin Quanity 必须是非负整数 数量列有空值、负数、小数、文本。 回 Excel 修正数量列，只保留 0 或正整数。
非法 Bin Grade Grade 不是 1 到 9 或 X。 统一 Grade 写法，去掉异常值。

14. 运行后怎么自查

给小白的最简单检查流程如下：

  1. 打开 05_allocation_report.xlsx。
  2. 进入 summary，看 status。如果是 OPTIMAL 或 FEASIBLE，说明有结果；如果是 INFEASIBLE，说明没有可用方案。
  3. 看 backend。如果是 large_batch，记住它是大表可行解，不是全局最优证明。
  4. 看 target_units、total_units、unit_gap。这三个值告诉你目标是多少、实际配了多少、差多少。
  5. 看 batches，确认每个母批的 loss 是否小于等于你输入的 loss_cap。
  6. 看 batches，确认每个母批的 distinct_lot_count 是否合理。
  7. 看 checks，筛选 ok = false。如果没有 false，说明自动校验通过。
  8. 看 warnings，确认有没有重要提示，比如大表模式、搜索空间过大、没有声明全局最优。
一条简单判断： checks 没有 false，且 summary 的结果你能接受，这份方案才可以进入业务复核。
