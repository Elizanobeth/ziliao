1一、Anthropic / Claude 产品总体盘点（2026）

可以把 Anthropic 的产品看成四层：模型层 → 平台与接口层 → 终端与工具层 → 订阅/商业包装层。围绕这四层，再叠加一些面向特定细分的解决方案（如 Small Business）。

1. 模型层（Model Layer）

核心是 Claude 4.x 族系（2026 上半年）[2][3]：

  • Claude Opus 4.6 / 4.7 / 4.8

    • 定位：旗舰模型，面向复杂推理、长链路 Agent、复杂编码与企业级知识工作。
    • 能力点：
      • 高难推理、数学证明、系统架构设计、复杂多步骤规划[2]。
      • 4.8 在推理、编码与“动态工作流”方面进一步增强，引入更强的 agentic 能力（Dynamic Workflows）[1][7]。
      • 支持最高 1M tokens 上下文（beta），适合整库代码、长文档与多源数据场景[1][5]。

  • Claude Sonnet 4.x 系列

    • 定位：性价比主力模型，日常企业工作负载主力。
    • 能力点：推理与编码能力接近 Opus，但成本和时延更低，在多数企业应用中是更优解[3][5]。

  • Claude Haiku 4.x 系列

    • 定位：轻量高速，适合高 QPS、响应延迟敏感场景（对话中台、小工具等）[3]。

总结：Anthropic 的“产品树根”其实就这三类模型：Opus / Sonnet / Haiku。所有 B 端产品，最终都要落到对这些模型的调用和编排上。

2. 平台与接口层（Platform & Interfaces）

这层是 To B 非常关键的“基础设施”。

  1. Claude API / Claude Developer Platform

    • 提供标准 REST / SDK 接口调用 Claude 模型[3][21]。
    • 支持：
      • Messages API（对话/补全）
      • Batch API（离线大批量任务）
      • Prompt Caching（提示缓存降本）
      • Compaction / token 管理工具（自动摘要和上下文裁剪）等[21]。
    • 可在 Anthropic 自有云 或第三方云（AWS Bedrock、Google Gemini Enterprise Agent Platform / Vertex AI、Microsoft Foundry 等）上使用[5][6][18]。

  2. Model Context Protocol（MCP）

    • Anthropic 提出的开放标准，用于把 LLM 与外部数据源、工具、SaaS API 做标准化连接[8]。
    • 功能：
      • 定义统一协议，让 Claude 能“安全地”访问数据库、HTTP API、本地文件、SaaS（如 Jira、Salesforce、Figma）等[8]。
      • 现在已经被捐赠给 Linux Foundation 下的 Agentic AI Foundation，成为行业通用标准之一[8]。
    • 对企业意义：
      • 让 Claude 作为“智能体中枢”时，可以更容易、安全地挂接到你现有 IT / 数据 / 业务系统。

  3. Claude Managed Agents（托管智能体平台）

    • 2026 年 4 月发布的 Managed Agents 是专门为企业级 AI Agent 场景做的托管运行时[9]。
    • 核心卖点：
      • 提供“一套托管 Agent Harness + 托管基础设施”：你只负责写 Agent 逻辑与工具列表，Anthropic 负责会话循环、长时间运行、状态管理、崩溃恢复、并发、扩缩容等[9]。
      • 典型计费：约 $0.08 / session-hour，另按模型 token 收费[9]。
    • 对比“自己起一堆容器跑 Agent”：
      • 你不再需要 DevOps 团队去维护长时间跑的 agent 服务，极大降低企业落地门槛。

3. 终端与工具层（Apps & Tools）

这一层是用户直接接触的“产品界面”，包含 Web、桌面端、IDE 插件等。

  1. claude.ai（Web 应用）

    • 面向个人与团队的 Web 聊天与协作环境。
    • 核心功能：
      • Chat + Projects（项目空间）
      • Artifacts（结构化输出：代码片段、图表、页面等）
      • File upload / 多文件分析
      • Memory（持久记忆）等[21]。

  2. Claude Desktop / Claude Cowork

    • Claude Cowork：2026 年 1 月发布的桌面“协作模式”[Cowork]。
    • 特点：
      • 运行在本地桌面应用中，可读写本地文件、创建文档、生成表格、管理项目等。
      • 支持 Connectors / Plugins / Scheduled Tasks / Dispatch / Computer Use 等高级能力：
        • 例如：定时任务、自动执行多步工作流；直接控制浏览器、Office、Slack 等[21]。
    • 定位：不是简单的聊天窗，而是“桌面上的数字同事”（knowledge worker agent）。

  3. Claude Code（Agentic Coding System）

    • 终端与 IDE 原生编程助手[6][17]。
    • 核心能力：
      • 读取大规模代码仓，理解架构；
      • 批量改动多文件、生成/重构代码、写测试、跑命令、操作 Git[6][17]；
      • 有完整的多层架构（六层上下文 / 工具治理 / UI / 扩展织物 / 记忆恢复等）[16]。
    • 部署形态：
      • CLI 工具（本地终端），支持 Pro / Max / Team / Enterprise 等账号；
      • 深度集成 VS Code、JetBrains、GitHub 等；
      • 在企业环境中，可以通过 Claude Code Enterprise 部署模式 + API 网关接自建开源模型，实现“Claude + 自建模型”的混合架构[14]。

  4. Claude Design（Anthropic Labs 产品）

    • 2026 年 4 月推出的新产品，面向视觉设计与原型制作[11][12][13]。
    • 能力：
      • 从文字 prompt 生成交互式原型、演示文稿（Slides）、落地页、UI 线框图；
      • 与代码仓和设计文件结合，在 onboarding 时自动学习团队 Design System（组件、tokens、交互规范），之后按品牌规范出图[11][13]。
    • 面向：Product / Design / Marketing 团队，用于品牌一致的视觉输出。

  5. Claude for Small Business

    • 面向中小企业的预配置方案[19]：
      • 自带 15 个预置工作流，覆盖财务、运营、销售、市场、HR、客服等；
      • 深度集成 QuickBooks、PayPal、HubSpot、Canva、Google Workspace、Microsoft 365 等 7+ 主流 SaaS[19]。
    • 形式：以 Cowork 插件 / 连接器 + 预置 Skills / 工作流 形式出现，用户只需在已有 SaaS 中“打开 Claude 开关”即可。

4. 订阅与商业包装层（Plans & Packaging）

这一层是你从“买工具”和“签企业协议”的角度看 Claude 的方式。

主线订阅产品线大致为[20][22]：

  • Free：有限额度、仅 Web，适合个人体验；
  • Pro（$20 / 月）：个人高频使用者，更多用量和更强模型访问；
  • Max（$100–$200 / 月）：超高用量及更多高级特性（如更高速/更多上下文）；
  • Team（约 $25–$30 / 人 / 月）：小团队 / 中小企业共享空间 + 管理功能；
  • Enterprise（自定义报价，通常起步 $20–$60 / 人 / 月，使用量单独计费）[22]：
    • 提供更大的上下文（如 500K–1M tokens）、扩展安全与合规功能、SCIM、审计日志、Compliance API、区域数据驻留等[1][20][23]。

To B 的重点，就是 Team / Enterprise + API / MCP + Claude Code / Cowork / Managed Agents 这几个组合。

2二、面向企业（To B）的产品与能力详解

下面聚焦你关心的 To B 侧——即企业级、组织级的产品与功能。

1. Claude Team & Enterprise（组织级 SaaS）

1.1 Team 计划

  • 定位：5–150 人左右的团队，共享 Claude 资源[20][22]。
  • 关键特性：
    • 共享 Projects / Artifacts / 文档；
    • 基本的管理功能：
      • 成员管理
      • 基本配额与消费可视化
      • 与 Slack / Microsoft 365 等协作工具集成[20]。
    • 可使用 Claude Code（Team 版本） 与部分 Cowork 功能。

适用：希望统一采购、统一管理员工 Claude 访问的小型公司或业务部门。

1.2 Enterprise 计划（重点）

Enterprise 是 Anthropic 真正意义上的 企业级 AI 平台包装[1][20][22]：

  • 包含内容（通常“在 Team 之上”的附加项）：
    1. 安全与身份治理
      • SSO（SAML / OIDC）
      • SCIM 用户与组同步
      • 基于角色的访问控制（RBAC）
      • 域捕获（Domain Capture）、IP 白名单等[1][20]。
    2. 数据与合规
      • 更长上下文窗口（官方提到企业版可达 1M tokens）[5]；
      • 自定义数据保留策略与日志留存；
      • SOC 2、ISO 27001、HIPAA 准备度等合规标准[1][23]；
      • Compliance API：给 SIEM / GRC / CASB 等系统提供访问日志与事件流，方便审计与风险监控[24]。
    3. 使用治理与可观察性
      • 管理控制台：自定义角色权限、消费预算、连接器管理（如限制某些连接器只允许特定团队使用）[24]；
      • 自定义 Admin Role：允许非 Owner 角色管理账单、隐私等设置[24]。
    4. 高级产品能力
      • 更大的上下文窗口（500K–1M tokens）；
      • 企业搜索、组织级 Projects / Artifacts；
      • Cowork / Claude Code / Claude Design 的企业级权限配置与日志；
      • 通过 MCP 和 Managed Agents 与内部系统深度集成的能力。

计费方式：

  • 基本 Seat 费用（通常 ~$20–$60 / 人 / 月）只覆盖“访问权”，所有 AI 使用量按 API token 单独计费，价格接近 API 公价[22]。
  • 换言之，Enterprise 更像是“把 Anthropic 当成内部 AI 基础设施”（Infra），而不是只买一个 SaaS。

2. Claude Code Enterprise（企业级开发与运维场景）

Claude Code 对 B 端的影响极大，可以理解为 “企业级 AI 编程与技术运维操作系统”[6][16][17]：

  1. 核心价值

    • 直接嵌入开发者日常工具链（终端 / IDE / Git / CI/CD）；
    • 具备多层架构和上下文系统：
      • 六层架构（入口 / 命令与技能层 / 核心引擎层 / 服务层 / 通信层 / 基础设施层）[16]；
      • 多级记忆（会话记忆、项目记忆、团队记忆）；
      • Skills / Hooks / SubAgents 等可扩展机制[16][17]。
    • 在企业中已经发展成 Agentic AI 底层基础设施：从一个工具演变为核心开发底座[15][16]。

  2. 企业版特性（结合多篇企业部署指南）[14][15][17]：

    • 可通过 API 网关对 Claude Code 的出站请求统一监控与过滤；
    • 支持与自建/开源 LLM 结合，例如通过 LiteLLM Proxy 统一路由“主线任务给 Claude，简单/隐私敏感任务给自建模型”[14]；
    • 提供 代码安全分析（Code Security） 仪表盘：扫描代码缺陷、生成补丁、支持安全团队审批与回滚[25]。

  3. 典型 To B 用法

    • 大企业内部：作为统一的“AI Pair Programmer / DevOps Agent”，与企业 GitLab/GitHub、Jira、内部文档、日志系统等连通；
    • SaaS / 平台厂商：将 Claude Code 能力以白标/深度集成形式嵌入自家开发平台或 IDE 解决方案。

对 供应链类企业 而言，Claude Code 的价值并不只是“写业务代码”，更在于：

  • 快速改造遗留 ERP / WMS / TMS / APS 系统；
  • 自动生成 ETL、清洗脚本和分析管道；
  • 编写与维护 MCP Server / API 集成，帮助 Claude Agent 接入各个业务系统与数据库。

3. Claude Cowork（企业知识工作场景）

Cowork 是一个运行在桌面端和 Web 侧的 多步知识工作智能体模式：

  • 为企业带来的能力[21]：
    • 连接 Slack / Google Drive / Microsoft 365 / Asana / Figma 等应用；
    • 通过 Connectors / Plugins / Scheduled Tasks / Dispatch / Projects / Computer Use 等功能，自动执行多步骤任务：
      • 如：收集一周销售数据 → 生成报表 → 产出 PPT → 发邮件给指定团队；
  • 在 Enterprise / Team 中：
    • 管理员可以统一控制哪些 Connectors 可用，哪些仅允许特定团队使用[24]；
    • 通过 Compliance API、MCP Governance 机制控制智能体对内部系统和工具的访问权限[24]。

对 B 端尤其是供应链企业，Cowork 非常适合：

  • 日常运营报表自动化；
  • 异常监控与告警（如库存偏差、订单异常）；
  • 多系统信息整合（跨 ERP/CRM/物流平台）。

4. Claude Design 与 Claude for Small Business（行业与职能解决方案）

虽然这两类产品一部分也会被个人或小团队使用，但其设计初衷明显偏 B 端：

  1. Claude Design（Anthropic Labs）[11][12][13]

    • 通过读取代码仓和设计文件，自动构建团队 Design System；
    • 支持原型 / 幻灯片 / 单页文档 / 互动站点等输出；
    • 对大中型企业内的 品牌 / 市场 / 产品 / 设计团队，是统一视觉标准和提高产能的一个组件。

  2. Claude for Small Business[19]

    • 自带 15 个预构建工作流与 7 个主流应用连接器；
    • 让中小企业可以在原有财务、营销、运营工具中直接启用 Claude 做自动化处理；
    • 属于标准化程度更高的“打包方案”，本质上是 Claude + Cowork + Skills + Connectors 的行业化封装。

  • 如果你只买 Enterprise 订阅 而不想自建代理：

4四、给你做内部决策或方案时的建议

  1. 先从订阅层选主方案

    • 中小团队：优先考虑 Team，享受较低座位价与足够的管理功能；
    • 大中型企业 / 有严格合规要求的供应链、金融、制造企业：
      → 考虑 Enterprise + API，把 Claude 当基础设施引入，并在合同中明确数据不用于训练、数据驻留与审计要求。

  2. 同时规划“工具层 + 平台层”组合

    • 研发 / IT 场景：重点压在 Claude Code + API + MCP，配合自有中间层与 API 网关；
    • 业务运营 / 供应链场景：重点压在 Cowork + Managed Agents + MCP，用 Connectors 和 Skills 把 Claude 接到你的 ERP / WMS / TMS / CRM 等系统。

  3. 产品架构图可进一步细化为“本企业视角”

    • 你可以在上面那张文本架构图基础上，再加一层：
      • 把你现有的系统（SAP、Oracle、金蝶、用友、WMS、OMS 等）画在两侧；
      • 用箭头表示：通过 MCP / API / 自建 Agent Server 与 Claude 平台相连；
      • 将 Claude Code 放在“工程支撑”一侧，将 Cowork 放在“运营与管理者桌面”一侧，形成清晰的职责边界。
5小结

  • Anthropic 当前的产品家族：
    从底层的 Claude 模型（Opus / Sonnet / Haiku），到上层的 API / MCP / Managed Agents，再到终端形态的 claude.ai、Claude Code、Cowork、Claude Design，最后通过 Free / Pro / Max / Team / Enterprise / Small Business 这些订阅计划面向不同客群。

  • To B 产品的核心：

    • 组织级订阅：Team / Enterprise（身份、权限、合规、日志）。
    • 开发与运维：Claude Code Enterprise + API + MCP。
    • 知识与业务协作：Cowork + Projects + Artifacts + Connectors。
    • 托管执行：Claude Managed Agents（长时间运行的自动化智能体）。

  • 产品架构图可以抽象为四层 + 订阅包装，你可以按照上文文本版图进一步画成 PPT 图示，用于内部对齐和供应商评估。
