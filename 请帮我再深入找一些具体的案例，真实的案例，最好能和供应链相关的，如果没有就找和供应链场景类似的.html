2.2 n8n 工作流：海关清关单证自动校验（多文档一致性 + 合规）

场景类型：国际物流 / 报关合规（供应链下游的合规关口）

业务问题

  • 国际出货前，需要人工逐份检查以下文件是否一致、合规：
    • 商业发票（Invoice）、装箱单（Packing List）、提单/空运单（B/L / AWB）；
    • 原产地证（COO）、报关单、危险品声明、健康/植检证等。
  • 如果字段不一致或 HS 编码错误，会导致：
    • 清关延误、货物扣押、罚款甚至退运。

Claude + n8n 方案

  • 触发方式：
    • 新出货单证上传到 Google Drive/S3，或通过 Webhook 提交；
  • 工作流步骤（简化）：
    1. 汇总一个出货的所有文件；
    2. 提取每份文件文本内容（发票金额、重量、数量、HS 码、目的国等）；
    3. 用 Claude 做跨文档一致性检查：
      • 值、重量、数量、HS 码在不同单证间是否一致；
      • Incoterms、币种、原产地是否统一；
    4. 基于目的国规则，让 Claude 做一次「合规验证」：
      • HS 分类是否合理；
      • 目的国是否对该货物有限制或额外要求；
      • 文件日期/有效期是否合理；
    5. 结果：
      • 生成结构化校验报告：CLEAR / HOLD / REJECT；
      • 对 HOLD/REJECT 的情况自动在 Slack 通知、发邮件给出口方，并在 Jira 建合规工单；
      • 在 Airtable/Google Sheets 中更新这票货的合规状态和审计日志。

AI 侧关键检查点

  • 字段完整性（必填项是否都有）；
  • 跨文档一致性；
  • HS 码与货物描述是否匹配；
  • Incoterms、发票价值、币种三者一致性；
  • 原产地与关税优惠（如自贸协定）对应关系；
  • 是否触及敏感/受限货物或制裁名单；
  • 日期逻辑是否合理（证书不过期）。

启发

  • 这是典型的「多文档、多规则校验」问题，供应链里非常多：
    • 合同 vs 订单 vs 发票 vs 收货记录；
    • PO、交期、入库记录的一致性；
  • Claude 非常适合做：
    • 文本信息抽取 + 跨文档规则检查；
    • 生成 人类可读的审计报告 + 机器可读的结构化结果。

        • 数据不被用于训练；
        • 有完整日志和 Compliance API 可供审计；
      • 对 MCP 接入的系统（ERP/WMS/TMS 等）设置清晰的权限边界和审计规则。
7小结
  • 真正与供应链高度相关的 Claude 实战案例，已经从「概念 PoC」走到：
    • 配送异常处理（DoorDash）；
    • 供应商 RFI 评估与对比；
    • 清关与合同多文档合规校验；
    • 库存补货与供应链网络优化（含可持续目标）；
    • 车队与设备的预测性维护；
    • 遗留供应链 IT 系统的现代化改造。
  • 若你现在要做供应链 AI 规划，可以直接以这些案例为模板：
    • 短期抓「异常+文档」提高效率；
    • 中期切入「库存/产能+网络优化」提升决策质量；
    • 同步用 Claude Code 给底层系统「换发动机」。
